# Defense dashboard

The seven pages are Overview, Live monitoring, Incidents, Security posture,
Cybersecurity quality, Model & research, System & evidence. Quality includes
contextual Fusion and sensitivity tabs. Observation details show real SHAP and
robust deviations; evidence drawers expose sanitized provenance. Incident
details retain observation membership and reviewed posture links.

## Launch

```bash
cd /home/saintdomix/dissertation_model
.venv/bin/python -B scripts/run_demo.py
```

Open `http://127.0.0.1:8000`. The launcher serves the bundled frontend and API
in one process. No external CDN, font, chart service or model training is needed.

## Explicit modes

**ACCEPTED EVIDENCE REPLAY** is the default. Select locked attack holdout or blind
benign test, then optionally a specific run. These are actual saved accepted
predictions, not fake events or a simulation. Replay never executes a model.
Offline predictions lack an original emission timestamp: Fusion uses the
observed window end as an explicitly labelled replay evidence clock. Stable
replay ordinals/IDs are application projection identifiers, not invented live
emission evidence. The 300-second horizon is anchored to evidence time.

**LIVE_LAB** reads the accepted-v2 journal. It does not substitute replay when
unavailable. Click Start saved-model monitoring to explicitly launch the existing
passive runner, or select an externally managed session at backend startup:

```bash
PRODUCT_RUNTIME_SESSION=runtime/behavioral_v2/operator_session \
  .venv/bin/python -B scripts/run_demo.py
```

The path must remain beneath `runtime/behavioral_v2/`. A configured external
process is not claimed running without a handle. No raw log is opened by API
requests. Start requires existing Apache read permission; the owned runner,
not the API, consumes the configured authorized log. No controlled attack
generator is exposed in the UI. Stop is graceful; changing to replay stops the
UI-owned live child first. Backend shutdown also stops its owned child.

For defense: inspect Overview → Model/research → select benign replay and
observe suppressed UNKNOWN → select controlled SQLI run → inspect incident,
SHAP and Quality/Fusion. Then, if operational prerequisites are ready, switch
to Live laboratory and start passive monitoring while browsing Moodle normally.
Never call replay live, raw windows independent attacks, or CQI a probability.

The full report link explicitly retains its historical v1 M3C scope. A newly
accepted-v2 full narrative report/export is not generated by this UI run.
